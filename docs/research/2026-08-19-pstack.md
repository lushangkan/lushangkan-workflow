# pstack 调研

## 1. pstack 是什么

pstack 是 Cursor 的开发者工具插件。它把作者 Lauren Tan（GitHub 用户名 `poteto`）日常使用的工程原则、工作流 skill、playbook 和专用 subagent 打包到 Cursor 中。它的目标不是多写代码，而是让 AI 写更少、质量更高、可验证的代码，并在此前提下安全地并行使用多个 agent。[来源：README](https://github.com/cursor/plugins/blob/main/pstack/README.md) [来源：插件元数据](https://github.com/cursor/plugins/blob/main/pstack/.cursor-plugin/plugin.json)

核心入口是 `/poteto-mode`。它读取用户请求，从 22 个 playbook 中选择一种，再按步骤调用调查、架构、TDD、评审、验证、并行分工和交付等 skill。插件还提供 `poteto-agent`，让父 agent 可以按同一套规则委派完整任务。[来源：README](https://github.com/cursor/plugins/blob/main/pstack/README.md) [来源：Poteto Mode](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md)

名字 `pstack` 的官方展开或词源**未确认**。首发 PR 只把它描述为“Lauren Tan 的工作风格和路由 skills”；README 又把它与作者 `poteto` 直接相连。因此，把名字理解为“poteto 的 stack”是合理推测，但仓库没有明确这样定义，不能当成已证实事实。[来源：首发 PR #73](https://github.com/cursor/plugins/pull/73) [来源：README](https://github.com/cursor/plugins/blob/main/pstack/README.md)

## 2. 它解决什么问题、面向什么场景

pstack 针对的问题是：AI 可以提高代码产量，却容易产生低质量、难验证的代码；多个 agent 并行后，这个问题还会放大。它用固定原则、任务路由、可核验的完成条件、真实运行验证和多模型复核来约束执行质量。[来源：README](https://github.com/cursor/plugins/blob/main/pstack/README.md) [来源：Poteto Mode](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md)

它面向 Cursor 中的非简单工程工作，包括调查、修 bug、性能分析、功能开发、重构、原型、UI 对齐、skill 编写、评测、PR 维护、长时间自主运行和多 agent 项目编排。简单任务也能使用，但 `Orchestrate` 明确只适合跨多天、多个堆叠 PR、几十到上百个 subagent 的项目；单个 agent 能在一个 session 内完成的工作应走较轻的流程。[来源：playbook 列表](https://github.com/cursor/plugins/blob/main/pstack/README.md) [来源：Orchestrate](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/orchestrate.md)

它不是通用项目管理产品。仓库把它注册为 `developer-tools` 类插件，能力主体是 Markdown 形式的 skills、agents 和 playbooks。它依赖 Cursor chat、Todo、Task subagent、worktree、PR 和可选的 Graphite 等执行环境，而不是提供独立的 roadmap、看板或 milestone 服务。[来源：插件元数据](https://github.com/cursor/plugins/blob/main/pstack/.cursor-plugin/plugin.json) [来源：首发 PR #73](https://github.com/cursor/plugins/pull/73)

## 3. 怎么用

1. 在 Cursor chat 运行 `/add-plugin pstack` 安装插件。[来源：安装指南](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/01-setup.md)
2. 运行 `/setup-pstack`。它检测可用模型，按代码、判断、评审 panel 等角色配置模型，并写入 `~/.cursor/rules/pstack-models.mdc`。配置主要对新 session 生效。[来源：安装指南](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/01-setup.md) [来源：setup-pstack](https://github.com/cursor/plugins/blob/main/pstack/skills/setup-pstack/SKILL.md)
3. 在任务开头输入 `/poteto-mode <目标和可检查的完成条件>`。例如：`/poteto-mode add a --json flag to this command. text output stays byte-identical. verify both.`[来源：安装指南](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/01-setup.md)
4. `/poteto-mode` 先读工程原则，再匹配 playbook，把步骤复制进 Cursor Todo，随后调用需要的 skill。它是 sticky mode，同一对话内会继续生效，直到用户退出或切换新任务。[来源：路由指南](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/02-poteto-mode.md) [来源：Poteto Mode](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md)
5. 长任务可以给出可判定的完成条件、独立 worktree、权限和停止条件，再配合 Cursor 内置 `/loop`。多项目单元可选 Autonomous run、Autopilot 或 Orchestrate。[来源：overnight 指南](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/07-overnight.md)

多数用户只需直接使用 `/poteto-mode`。`/how`、`/why`、`/architect`、`/swarm`、`/interrogate`、`/tdd` 等命令是按需直达入口，通常由主模式自动调用。[来源：README](https://github.com/cursor/plugins/blob/main/pstack/README.md)

**文档完整度高。** README 给出安装、入口、22 个 playbook、全部主要 skill、principle、subagent、依赖与限制。另有 10 篇循序指南，覆盖安装、理解、设计、实现、验证、交付、过夜运行、原则和常见问题。关键 playbook 也写到了输入、步骤、状态文件和验证规则。[来源：README](https://github.com/cursor/plugins/blob/main/pstack/README.md) [来源：指南目录](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/README.md) [来源：Orchestrate](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/orchestrate.md)

**成熟度判断为“可用，但仍属快速演进期”。** 当前插件元数据版本是 0.14.1，尚未到 1.0；两周内曾连续增加大批 playbook 并调整模型默认值。它的工作流和文档已经很丰富，但 API、默认模型、playbook 边界继续变化的风险仍高于稳定版产品。[来源：插件元数据](https://github.com/cursor/plugins/blob/main/pstack/.cursor-plugin/plugin.json) [来源：0.13.0 提交](https://github.com/cursor/plugins/commit/b047069f4f3a73e87dd1f11f7913386d25876b91) [来源：0.14.0 提交](https://github.com/cursor/plugins/commit/99559f2f52047978602ef365589275831e76af07)

## 5. 与“平台 → 里程碑 → 薄片”规划的关系

pstack **与阶段和薄片有关系，但不是里程碑清单维护系统**。

- 它能生成分阶段实施计划。`Multi-phase plan` 要求大型计划使用 `overview.md` 加 phase 文件，并建议每个 phase 只做一个函数或类型加测试、一个 bug fix，通常只改 2 至 3 个文件；每个 phase 应独立可交付。这与“把当前工作拆成可验证薄片”高度相似。[来源：Plan reference](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/references/plan.md)
- 它能在执行期保存项目状态。`Orchestrate` 维护 `overview.md`、`units.tsv`、`frontier.json`、`ledger.tsv`、`status.md` 等文件，追踪工作单元、PR 前沿和验证结果。这是大型交付程序的运行账本，不是产品路线图。[来源：Orchestrate](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/orchestrate.md)
- 它没有“平台 → 里程碑 → 薄片”的领域模型，也没有里程碑状态、目标日期、优先级、依赖、滚动展开规则或专门的维护命令。计划 playbook 的交付物是一次性分阶段实施计划；`Orchestrate` 的状态对象则是正在执行的 unit、branch、PR 和验证记录。[来源：Plan reference](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/references/plan.md) [来源：Orchestrate](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/orchestrate.md)
- 它甚至明确说明默认不提供独立 planning skills，因为作者倾向使用 Cursor Plan Mode，且认为“最好的 spec 是代码”；有计划需求时才由 `/poteto-mode` 覆盖。因此，把 pstack 当成长期 roadmap 的权威存储，与其设计重心不符。[来源：README 的 planning 说明](https://github.com/cursor/plugins/blob/main/pstack/README.md)

对单人开发者而言，pstack 可以放在清单工具之后：里程碑工具决定“现在推进哪个里程碑”，pstack 再把当前里程碑拆成小 phase、执行、验证和交付。若强行用 `overview.md` 或 `units.tsv` 保存里程碑，虽然技术上能写进去，但需要自定义 schema、滚动维护规则和路由 skill；那是基于 pstack 另造一套能力，不是 pstack 已提供的功能。[来源：Plan reference](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/references/plan.md) [来源：Orchestrate](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/orchestrate.md)

**能否当里程碑维护工具：不能。它能拆解和执行当前阶段，但没有长期、滚动式维护里程碑清单的模型与入口。**
