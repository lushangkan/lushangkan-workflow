#### 1. 输出规范 skill（2026-08-13）

**决定建一个输出规范 skill**，融合 i-have-adhd（github.com/ayghri/i-have-adhd，10 条输出塑形规则 + 发送前检查清单）。

三层结构：
1. **语言规范**：默认简体中文；固定技术术语保留英文；代码 comment 中文；句子自然清楚，忌翻译腔/模板腔。
2. **ADHD 输出塑形**（采纳）：答案/行动先行；无开场白无收尾客套；多步任务编号；每轮重述状态；抑制岔题；列表 >5 分层；报错陈述事实（原因+修法）；发送前检查清单。

#### 2. 翻译腔实证分析（2026-08-13，基于 2026-07-25 会话 B）

素材：旧机挂载盘 `/mnt/vhdx/home/zara/.omp/agent/sessions/-projects-lushangkan-workflow/`，会话 B（`2026-07-25T12-32-36`）同一上下文中 GPT-5.6 答 57 条后切 Claude Opus 4.8 答 58 条，含同一问题（"我想要A但可再优化变小"）的双模型回答对。

**核心发现：差距主要在信息拓扑，不在句子语法。**

量化（GPT 12 条长消息 vs Claude 17 条）：平均每条 2499 vs 845 字；标题 113 vs 20；代码块 114 vs 12；列表项 405 vs 61；"我认为/我建议" 9 vs 1；"如果" 15 vs 2；"不是X而是Y" 9 vs 0；表格行 21 vs 43（Claude 更多）。

GPT 病灶（→ skill 判据）：
1. 抽象分类法前置，读者须先背框架
2. 结尾追加开放选项（"还有一个更保守的选择"），决策点不收敛
3. 元话语："我认为/换句话说/需要注意的是"
4. "不是 X，而是 Y" 修辞框架滥用
5. 伪代码块/目录树表达概念（应用表格）

✅ 新增写作规则 7 条：具体判断先行；决策点 ≤2 且带推荐值；删元话语；禁"不是X而是Y"；映射用表格；顶层章节 ≤4；句子主谓宾直陈、删名词化、砍长定语链。

#### 3. 用词层病灶（2026-08-13，用户指认真实样本）

用户明确：结构问题无伤大雅，**句子用词才是核心痛点**。实证：GPT 全文 50 处引号自造词（强治理、薄编排、工程纪律、纪律 Skill、收尾沉淀、真实用户表面、人手触发……），Claude 16 处且多为引用真实 artifact 名。

✅ 新增用词规则 5 条：
1. 不造词——不用需解码的自造术语；新概念首次出现用一句人话定义
2. 人话检验——"中国人面对面这么说话吗"，不说就改（人手触发→手动触发）
3. 删辅助词——"我目前最想建议的方向是 X"→"我建议 X"
4. 比喻必须有着落——"薄/重/轻"同句内给参照，给不出就删
5. 抽象名词必须落地——"纪律/治理/编排"下一句给出具体所指，给不出换具体说法

skill 写作规范 = 结构层 7 条 + 用词层 5 条。

#### 5. 无障碍标准背书与骨架重定（2026-08-13）

用户披露：**本人有阅读障碍 + ADHD**，此 skill 属无障碍适配，非单纯偏好。

##### 规则清单（正面表述版，按 ISO 四原则）

基础：默认简体中文；固定技术术语保留英文原词；代码 comment 用中文。

**relevant 只给需要的**
- 只写读者需要的内容（ISO 5.1.6）
- 待决策事项收敛到 2 个以内，各带推荐值（GPT 实证）
- 估算有依据才给，没依据就说不确定（i-have-adhd 改造 + Matt v1.2.3）
- 数字、日期、结论只写来源里有的；确定程度按原文保留（Fenng / STE）

**findable 容易找到**
- 判断或答案放第一行（i-have-adhd 1 + ISO 5.2.2a）
- 标题写成能预测下文的样子（ISO 5.2.4）
- 映射关系用表格；代码块只装能运行的代码或命令（GPT 实证）
- 警告和破坏性提示写在指令之前（ISO 5.2.2e + STE）
- 顶层章节 4 个以内；列表超 5 项按必做/可选分层（COGA 4.6.3 + i-have-adhd 9）
- 第二个话题单独提出来问（i-have-adhd 4）

**understandable 容易读懂**
- 用日常词；新概念首次出现给一句人话定义（COGA 4.4.1 + 用户指认）
- 过一遍人话检验："中国人面对面这么说话吗"（用户指认）
- 判断直述，依据紧随其后（GPT 实证：元话语和辅助词）
- 直接说结论是什么（GPT 实证："不是 X 而是 Y" 9 次 vs Claude 0 次）
- 相对词同句给参照（COGA 4.4.4 + 用户指认）
- 抽象名词下一句给具体所指（用户指认）
- 一句一意，主谓宾直陈（COGA 4.4.3 / 4.4.5 + ISO 5.3.3）
- 一个概念固定一个术语（STE / Fenng）
- 指代写具体名称（Fenng）
- 写明执行者，区分系统自动和手动操作（Fenng）

**usable 容易使用**
- 每轮重述当前状态（COGA Objective 6 + i-have-adhd 5）
- 多步任务编号，一步一个动作，含"显而易见"的步骤（COGA 4.4.9）
- 报错给位置、原因、修法（i-have-adhd 8）
- 完成的工作给出怎么验证（i-have-adhd 7）
- 发送前过检查清单（i-have-adhd）
- 验收：用户看不懂就是违规（ISO 原则 4）

**让位条款**：要求详细解释时可写长；破坏性操作先确认；debug 三轮无进展停下质疑假设；规则与任务冲突时任务赢；引用原文保持原样；品牌文案、叙事文本、极短标签不机械套用。

##### 写作纪律（依据 writing-for-agents）

1. 规则改成正面目标。禁令会把被禁行为拖进上下文，反而更容易发生。硬护栏可保留禁令，但必须配正面目标。
2. 用已有词做锚（plain language、翻译腔、判决先行），不自造术语——skill 自身遵守自己的不造词规则。
3. 每条规则过 no-op 检验：它是否真的改变模型默认行为？不改就删。当前 A/B 只验证了整套规则，单条消融待测。
4. 单一来源：同一条规则只写一处，AGENTS.md 核心与 skill 全量之间用指针连接，不复制。
5. description 前置触发词，只列真正不同的分支。
6. 完成判据写成可检查的形式（"每条规则都有坏→好例子"而不是"例子充分"）。
7. 主文件只留必须每次读的内容，例子库和出处推到 references/。
