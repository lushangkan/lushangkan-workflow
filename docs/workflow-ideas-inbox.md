## 0. 最高优先级约束(2026-08-15)

- **一周半内搭完一个大平台**,很紧急。
- 微小维护和其他事先排除。
- workflow 重构要**围绕这个平台任务**来优化,不是纯理论设计。

## 1. 工作模式:异步

- 白天约 6 小时脑子清醒,能做决策。偶尔睡不好会整天无法工作。
- 不想同步等 agent 编码——等的时候会刷手机,忽略它已完成,浪费时间。
- 想学 Matt:在 GitHub issue/PR 提需求,后台跑 Docker 开发镜像,镜像领任务、做完、PR 提交。
- raft.build:agent 像群聊一样自主工作,给人和其他 agent 发消息。待研究这个平台怎么运作。

## 2. 基础设施

- **切换 harness**:OpenCode 不能让主 agent 指定 sub agent 的模型 → 考虑切 PI。
- **PI 的问题**:插件生态碎片,一个功能多个实现仓库。例:LSP 校验插件要劫持官方 edit 工具;hash editing 省 token 也要劫持 edit 工具。两者冲突,重复劫持。Oh My PI 是参考例子,但很多内容不需要。
- **Docker development container**:与本机开发环境同步,提供相同工具。整个 workflow 仓库变成一个 Docker 构建。
- **本机守护进程 / 编排器**:主动查询,按需启动 container 做事。

## 3. 新 skill 想法

- **模型能力清单 skill**:每个可用模型擅长/不擅长什么。配合动态 sub agent,做到"什么任务用什么模型"。需持续维护。
- **动态 sub agent 编排**:至少要有一部分负责。待定:放进大的项目编排 skill,还是单独拆。
- **领域建模 skill**:C4、ADR 等合成一个大 skill 专门负责。
- **自动记录决策**:模型现在不主动记决策和领域名词,要手动提醒。希望 skill 让模型自动记。
- **BMAD Party Mode**:多个岗位角色对同一问题做 review → 提取成 skill。
- **职位库 skill**:维护每个职位的 system prompt。用在 UIUX、写文档、party mode 等场景。
