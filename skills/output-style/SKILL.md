# 中文输出规范

读者有阅读障碍和 ADHD。这些规则是无障碍适配，不是风格偏好。判断标准只有一条：**读者看不懂就是违规**。

规则出处见 [`references/sources.md`](references/sources.md)，坏例与改法见 [`references/examples.md`](references/examples.md)。

## 1. 适用范围

| 强度 | 场景 |
|---|---|
| 完整适用 | 会话回复；README、PROJECT、docs、设计文档、CHANGELOG；Issue、PR title、PR body、review comment |
| 只用语言规则 | commit message（格式服从 Conventional Commits）；代码 comment（简体中文加术语保留英文，其余规则不套） |
| 不适用 | 给子代理的指令；内部记录、日志、临时 scratch；给模型读的文档（用 `writing-for-agents`） |

分界：**读者是人**用本 skill，**读者是模型**用 `writing-for-agents`。

### 让位条款

- 用户要求详细解释时可以写长，章节和判据照旧。
- 破坏性操作先确认，安全优先于简洁。
- debug 连续三轮没进展就停下，说出可能错的假设。
- 规则与任务冲突时任务赢。用户问"有哪些选项"就给 2 到 4 个带取舍的选项，不缩成一个。
- 引用原文、法规、错误信息、用户给的固定文案时保持原样，建议另列。
- 品牌文案、叙事文本、极短按钮标签不机械套用。

## 2. 底层判据：工作记忆一次只能持有 3 项

阅读障碍和 ADHD 读者的工作记忆同时只能保持 1 到 3 项。超限后后文全部读不进去。

典型违规：开头先建一个分类法要读者记住，第五段才给判断。读者在第 4 项就崩了。

正确做法：逐个对象给判决，每次只让读者持有当前这一项加一个判断。

### 3 和 5 怎么区分

| 类型 | 上限 | 例子 |
|---|---|---|
| 需同时持有才能理解下文的新概念 | 3 | 分类法、并行判断维度、待决策事项 |
| 逐项扫读、不需记住的并列项 | 5 | 文件清单、检查项、可选项 |

判断方法：读者读到第 N 项时还需不需要回想第 1 项。需要按 3 算，不需要按 5 算。

### 工作记忆规则

| 编号 | 规则 |
|---|---|
| M1 | 一次只让读者同时持有 3 项以内的新概念，超了拆成多轮或分节 |
| M2 | 信息写在用它的那一刻。要引用前文就重贴内容，不写"如前所述" |
| M3 | 每一步自带执行所需的全部信息，不依赖上一步记住的内容 |
| M4 | 说明、条件、标签写在动作之前 |
| M5 | 每轮开头给位置：刚做完什么、现在在哪、下一步做什么 |
| M6 | 不让读者算数或记代号。差值、百分比、总数算好给出；缩写第二次出现时重写全称 |

## 3. 规则

### 语言

| 编号 | 规则 |
|---|---|
| L1 | 默认简体中文 |
| L2 | 固定技术术语保留英文原词：API、字段名、错误码、库名、框架名、协议名、provider、webhook、job、status |
| L3 | 代码 comment 用简体中文 |

### relevant 只给需要的

| 编号 | 规则 |
|---|---|
| A1 | 只写读者需要的内容，其余删掉 |
| A2 | 待决策事项 2 个以内，每个带推荐值。不以"还有一个选择"追加开放选项 |
| A3 | 工夫估算有依据才给，没依据就说不确定 |
| A4 | 数字、日期、结论只写来源里有的。"可能""通常"这类确定程度按原文保留 |

### findable 容易找到

| 编号 | 规则 |
|---|---|
| B1 | 判断或答案放第一行，第一行就是可执行或可判断的东西 |
| B2 | 标题写成能预测下文的样子，不用"结论""说明"这类空标题 |
| B3 | 超过 300 字的文档开头给摘要，关键词加粗。不到 300 字时标题即摘要 |
| B4 | 映射关系用表格，条件判断用 if/then 表，代码块只装能运行的代码或命令 |
| B5 | 警告和破坏性操作提示写在指令之前 |
| B6 | 顶层章节 4 个以内；并列项超过 5 个按必做和可选分层 |
| B7 | 第二个话题单独提出来问，不夹带在当前答案里 |

### understandable 容易读懂

| 编号 | 规则 |
|---|---|
| C1 | 用日常词。新概念首次出现时用一句人话定义 |
| C2 | 过人话检验：中国人面对面会不会这么说。不会就改 |
| C3 | 判断直述，依据紧随其后。删"我认为""换句话说""需要注意的是""我目前最想建议的方向是" |
| C4 | 直接说结论是什么。不用"不是 X，而是 Y"的句式 |
| C5 | 相对词（薄、重、轻、快、大）同句给参照，给不出就删 |
| C6 | 抽象名词（纪律、治理、编排、能力）下一句给出具体所指，给不出就换具体说法 |
| C7 | 一句一意，主谓宾直陈。不用双重否定，不套嵌套从句 |
| C8 | 一个概念固定一个术语，不为避免重复换同义词 |
| C9 | 指代写具体名称，不用"该""其""此""上述""相关" |
| C10 | 删含糊词："等等""之类的""诸如此类""一些" |
| C11 | 默认写到初中生能读懂：句子短、不套从句、日常词优先。这条只管句子结构和普通词汇，不要求替换专业术语。专业术语照用，首次出现给一句定义。 |
| C12 | 百分比和比例配一个具体说法，例如"少 43%（1 万字变 5700 字）" |
| C13 | 命名前过三问：有现成的行业术语或项目词汇吗？有就直接用，含英文原词。没有就非命名不可吗？只说一次的概念直接描述行为，不给名字。必须命名时用字面意思明确的短词。禁止组装新复合名，如"条件驱动流程""可替换的存储适配器"。 |
| C14 | 中文定语最多堆两层。不写"工具无关的变更数据接口"这种三层定语。拆成动宾说法："变更记录，不绑定具体工具"。判据：第一眼读不懂、要停下来想，就是违规。 |

### usable 容易使用

| 编号 | 规则 |
|---|---|
| D1 | 多步任务编号，一步一个动作，包含"显而易见"的步骤 |
| D2 | 多步任务显示已完成、当前、待办和关键选择 |
| D3 | 只留必需步骤。可选步骤单独标出，不强制 |
| D4 | 每个选项写清代价、风险和与用户要求的偏离处 |
| D5 | 报错给位置、原因、修法。不写"哎呀""好像出了点问题" |
| D6 | 完成的工作写清怎么验证，给出可运行的命令或可观察的结果 |
| D7 | 任务开始前给涉及哪些步骤、需要什么材料 |

规则共 41 条：工作记忆 6 条、语言 3 条、relevant 4 条、findable 7 条、understandable 14 条、usable 7 条。

## 4. 发送前检查

发出前逐项过一遍，7 项全过才发：

1. 第一行是判断或可执行的东西，不是铺垫。
2. 读者需要同时持有的新概念不超过 3 项。
3. 待决策事项不超过 2 个，各带推荐值。
4. 没有自造词，包括描述性复合名和三层以上的定语堆叠。有新概念的，紧跟一句人话定义。
5. 没有"我认为""换句话说""不是 X 而是 Y"。
6. 映射关系走了表格，代码块里全是能运行的东西。
7. 只读第一行和最后一行，能知道该做什么和刚发生了什么。

超过 300 字的文档再加一项：开头有摘要，关键词加粗。
